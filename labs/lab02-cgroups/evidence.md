## 5. Troubleshooting and production implications

- `cgroup.controllers` describes controllers available to child cgroups at a hierarchy level; `cgroup.subtree_control` describes controllers enabled for children. They are related but not interchangeable.
- `cpu.max` expresses quota and period. Capture the actual value instead of inferring it solely from Docker flags.
- Increasing `nr_throttled` supports the conclusion that CPU quota throttling occurred during the sample.
- `memory.max` is a byte-based limit; `memory.current` is memory currently accounted to the cgroup, not only the application's explicit allocation.
- `memory.events`, container exit state, logs, and `OOMKilled` should be correlated before diagnosing an OOM kill.
- Resource limits help reduce noisy-neighbor risk, but do not replace namespaces, least-privilege capabilities, seccomp, AppArmor/SELinux, patching, or network controls.
- Direct cgroup operations require a correctly delegated hierarchy. Avoid writing root-level controller settings or moving unrelated processes.
